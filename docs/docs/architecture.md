# Architecture

`:dawn4k` is the WebGPU backend of this repository: it implements the public
Graphiks WebGPU contract (`org.graphiks.webgpu`) on top of Dawn's C API. This
page describes the layered design, the threading model and the two deliberate
contract divergences every reviewer must know: the borrowed `ArrayBuffer` of a
mapped range, and the absence of a common `GPUDevice.lost`.

## Layers

| Layer | Location | Role |
| --- | --- | --- |
| Generated bindings | `:dawn4k-native` → `org.graphiks.dawn4k.native` | kextract output over the pinned Dawn release; never edited by hand |
| Runtime & mailbox | `dawn4k/.../internal/DawnRuntime.kt`, `CallbackMailbox.kt`, `PendingOperation.kt` | direct caller-thread operations, explicitly progressed callback settlements and ownership tracking |
| Device sessions & resource ownership | `dawn4k/.../internal/DeviceSession.kt`, `OwnedReference.kt` | session-owned adapter/device/queue references; individually caller-owned resource references |
| Wrappers & mappers | `dawn4k/.../*.kt`, `dawn4k/.../mapper/*` | one `Dawn*` class per WebGPU interface; explicit name-based descriptor/enum tables |
| Public entry point | `dawn4k/.../DawnContext.kt`, `Adapter.kt`, `Device.kt` | `DawnContext.create(config)` → `requestAdapter` → `requestDevice` |

### Toolkit ownership layer

`dawn4k-toolkit-core` → `dawn4k` adds GPU-session lifetime, an OS-thread-pinned
owner and event progression. `dawn4k-toolkit-surface` → core adds retained native
targets, compatible-adapter bootstrap and frame scopes. `dawn4k-toolkit-glfw` →
surface adds desktop windows and the process-main-thread loop. Core and surface
share all nine backend Kotlin targets; GLFW declares only its three desktop
targets. None of these modules depends on Compose. The particle demo now uses
these public toolkit factories while keeping its scene, controls and restart
policy application-owned. See [Dawn4k toolkit](toolkit.md) for ownership, mobile
view retirement, execution modes and the distinction between supported variants
and executed platform validation.

### Generated bindings

The `org.graphiks.dawn4k.native` package is generated by kextract from the Dawn
release pinned in `bindings/dawn.lock.json` (see
[Native Dawn binding](native-binding.md)). The backend consumes it as-is: no
numeric constant is ever assumed, and every enum/flag conversion goes through a
named-constant table in `mapper/Enums.kt` and friends.

### Caller-owned threading and progression

The `:dawn4k` backend creates **no worker, dispatcher or event-pump job**. Native downcalls,
including async request issuance, execute on their caller. The application
chooses threads, ordering, event frequency and cancellation policy.

Call `DawnContext.processEvents()` explicitly: it drains one finite mailbox batch,
calls `wgpuInstanceProcessEvents`, then drains another batch. Concurrent or
reentrant progression is refused. User error callbacks run on this caller;
none of the suspend/await methods implicitly pumps events.
Uncaptured errors are delivered to the descriptor's callback without keeping an
internal history. Without a callback, or if it throws, stderr receives the GPU
error type and message; callback failures also include their stack trace and do
not interrupt event progression. Applications own their logging and retention.
Cancelling a wait does not cancel native delivery:
late owned results are released during explicit progression. Native completion
and Kotlin ownership transfer are tracked independently.

For shared-device concurrency request
`DawnConfig(implicitDeviceSynchronization = true)` **before requesting devices**.
It checks and requests Dawn's native `ImplicitDeviceSynchronization` feature,
merged with descriptor-required features. Default is `false`: the consumer must
then externally synchronize non-encoding calls too, including progression that
ticks devices. This is native synchronization, not a Kotlin scheduler or a
performance guarantee.

Each concurrent task exclusively owns its encoder and passes. Shared immutable
resources may be referenced by independent encoders. Join tasks before publishing
command buffers; order queue operations yourself. Never race map/unmap, mapped
memory access, destroy or close against resource use.

Dawn error scopes are **OS-thread-local**: push, validated calls and native pop
issuance must use the same OS thread. A consumer-owned single-thread executor
works on JVM; `Dispatchers.Default.limitedParallelism(1)` is serial but does not
guarantee thread identity.

### Device sessions and caller-owned resources

A `DeviceSession` owns the adapter reference it acquired (`wgpuAdapterAddRef`),
the device and its queue. Each resource wrapper owns its acquired native
reference independently, through a local `OwnedReference`:

- **refcount-only** objects (samplers, layouts, pipelines, encoders, …) are
  released by `close()` right away;
- **destroy-backed** objects (buffers, textures, query sets) are destroyed by
  `close()` and their native reference is released immediately afterwards.

The caller must close resources before their device. Closing a session releases
its queue, not its resource wrappers; forgotten closes can leak native references.
Device/adapter references remain owned until explicit progression settles device
loss and proves callback quiescence. There is no resource registry, finalizer or
implicit GC cleanup. Native destroy/release actions run on the closing caller.

`close()` is idempotent. Buffers, textures and query sets no longer retain a
destroyed native handle for later validation. Copied metadata remains readable,
but any operation using a closed native handle throws `IllegalStateException`
before a downcall. Guards are not use/close barriers: stop/join users and settle
pending operations before closure. Unclaimed asynchronous results still belong
to their issuing operation until ownership is transferred to a caller.

### Wrappers, guards and mappers

Each resource `Dawn*` wrapper owns its native reference; `DawnQueue` only borrows
the session-owned queue. Mappers cast WebGPU objects to
their Dawn wrappers; cross-device use is left to Dawn's WebGPU validation.
Pass encoders release their handle on `end()` and the render bundle encoder on
`close()`, so each carries a Kotlin guard refusing late commands with an
`IllegalStateException` **before** a downcall — `finish()` on a command encoder
or bundle encoder deliberately does *not* release, so finishing twice is left
to Dawn's own validation. Labels are Kotlin-side metadata: the C label views
keep their defaults on every downcall.

The external render-bundle and pass interfaces have no close operation.
`DawnRenderBundle` is explicitly `AutoCloseable`; cast an interface-typed bundle
to its Dawn wrapper to close it. Concrete `DawnComputePassEncoder` and
`DawnRenderPassEncoder` also provide close for exception cleanup: close releases
an abandoned pass without implicitly calling native end. Render-pass temporary
attachment views are released on both end and close.

## Toolkit session machinery

Each toolkit lifecycle component enforces one invariant that plain sequencing
cannot. A contributor changing `dawn4k-toolkit-core` or
`dawn4k-toolkit-surface` should know what each piece is for; the public rules
live in [Dawn4k toolkit](toolkit.md).

**Pinned execution owner.** A session's dispatcher is pinned to one OS thread
and remembers the thread it first saw, so a thread jump fails fast instead of
corrupting Dawn's OS-thread-local error scopes. `limitedParallelism(1)` is
serial without being pinned, so a borrowed dispatcher must provide the pinning
itself. The owner also refuses reentrant progression: session operations cannot
run inside an event pump, and a pump cannot run inside itself.

**Admission.** `gpu.run` pairs a non-reentrant mutex with a coroutine-context
marker. A nested `run` sees the marker and joins the outer admission instead of
deadlocking; a shutdown waits for that same admission as its application-work
drain barrier. `run` also registers its job with the lifecycle, which is how
device loss and fatal errors cancel exactly the admitted work.

**Transactional bootstrap.** Startup acquires native handles in order —
context, retention, adapter, device, presentation — and every step is covered by
a rollback action on a transaction; retention registers its rollback before
acquiring, so a cancellation during the acquire is covered too. Caller
cancellation never runs the
rollback inline: the retirement is owned by a `NonCancellable` scope, bounded by
`shutdownTimeout` per attempt, and retried until the transaction is empty. The
startup deadline runs on the real GPU clock, not the caller's — possibly
virtual — scheduler.

**Staged shutdown.** A shutdown retires the presentation, then closes device,
adapter and context with a drain between each stage, advancing a stage counter
only after success, so a retried attempt resumes where the previous one stopped.
Concurrent callers share one in-flight attempt; a timeout or failure preserves
the handles it has not closed yet, publishes the state and schedules a
background retry on the owner
while the application stays free to call `shutdown()` again.

**Target generations.** A target's native identity is a generation counter. The
presentation's async watcher and an in-flight `replaceTarget` can race; a
`detachTarget` whose generation no longer matches the active attachment is a
no-op, so a late detach can never kill the new target. Retention re-checks the
generation after its suspending `retain`, because the handle may change
identity while the lease is being pinned.

**Retirement acknowledgement.** Dawn keeps native references to a surface after
the application stops using it, so a host must not destroy its window or view
on its own schedule. A lease's `retire()` runs on the platform owner and returns
only once every surface reference is gone; a failed or interrupted retirement
stays registered and retryable instead of being assumed complete.

## The borrowed `ArrayBuffer` limitation

`GPUBuffer.getMappedRange` returns an `ArrayBuffer` that **wraps the actual
mapped memory** — a borrowed view, never a CPU copy. Once the buffer is
unmapped (or closed), the memory goes back to the device and the view is
**invalid**. This is deliberately **not guarded**: no wrapper can know which
views are still held. Never read or write a mapped-range view after `unmap()` —
doing so is undefined behaviour, not a Kotlin exception.

## Published WebGPU contract

`GPUBuffer.usage` and `GPUTexture.usage` return typed masks, preserving the
descriptor's bits, including unknown ones. `GPUDeviceDescriptor.requiredLimits`
accepts partial `GPURequiredLimits`: null properties use the pinned Dawn header's
32-bit or 64-bit undefined sentinel; explicit zero remains zero. Nullable slots
in pipeline layouts, vertex buffers, color targets, pass attachments and bundle
formats retain their indices and use the corresponding native empty-slot form.

`GPUDevice.awaitLost()` observes a shared native `GPUDeviceLostInfo` result.
Cancelling one observer neither destroys the device nor cancels other observers.
The consumer must progress loss notifications, even when no other GPU operation
is pending. Both callback routes are closed and proven quiescent before the
terminal result completes; later observers receive that same result. Device
`close()` explicitly destroys the native device; further `processEvents()` calls
settle its loss and release device/adapter references. Closing during progression,
with outstanding relevant operations, or with open context children throws before
mutating ownership. Stop/join producers, settle pending results, close devices
and adapters, drain teardown, then close the context. `hasPendingOperations()` is
a snapshot, not a shutdown barrier; idle permanent callback routes and loss
observers do not make it permanently true.

## Target coverage versus `:dawn4k-native`

`:dawn4k-native` publishes bindings for a wide matrix (JVM, Android, macOS,
Linux x64, Android NDK, iOS and tvOS). The `:dawn4k` backend now declares the
same Kotlin matrix: JVM, Android, `macosArm64`, `linuxX64`, the three iOS
targets and the two tvOS targets. Android landed last, after `webgpu-api`
gained the borrowed-address `ArrayBuffer.wrap(address, size)` factory that a
GPU-mapped range requires (Graphiks-org/WebGPU#135):

| Target | `:dawn4k-native` | `:dawn4k` | Validation status |
| --- | --- | --- | --- |
| JVM | yes | yes (validated) | JVM tests and the GPU suite on Metal |
| `macosArm64` | yes | yes (validated, Metal) | K/N tests and the GPU suite on Metal |
| `linuxX64` | yes | yes | a Linux host with a GPU is required to validate |
| iOS (`arm64`/`x64`/simulator) | yes | yes | compiled, test binaries disabled like `:dawn4k-native` — validating requires a device or a booted simulator |
| tvOS (`arm64`/simulator) | yes | yes | compiled, test binaries disabled like `:dawn4k-native` — validating requires a device or a booted simulator |
| Android | yes | yes | compiled like `:dawn4k-native` (no host-test compilation); the borrowed mapped range goes through the upstream `ArrayBuffer.wrap(address, size)` |

On Android the borrowed `getMappedRange` view and the upload fast path ride
`webgpu-api`'s public factories: `wrap(address, size)` for the borrowed view,
and the direct `ByteBuffer` address for uploads, with a copy fallback whenever
the address accessor is unavailable — the same degradation contract as the
JVM actual. The `suite-acid-tests` dependency lives in a desktop-only
intermediate test source set because the published acid suite has no Apple
mobile variants. The public-contract acid witness (`PublicContractGpuTest`)
runs through standard desktop test tasks; common GPU tests also run on Apple
simulators. Test utilities report missing adapters, while strict CPU CI requires
an adapter. The JVM and Android runtimes share their
lock actuals through a `jvmSharedMain` source set.

## Ownership rules for callers

- close **sessions before their runtime**, and adapters/devices in reverse
  creation order (`DawnContext.close()` is idempotent, as is every `close()`);
- a resource belongs to exactly one device session — passing it to another
  device is refused before any handle is read;
- command buffers cannot be re-submitted, and a finished encoder must not be
  finished again (Dawn observes both as uncaptured validation errors).
