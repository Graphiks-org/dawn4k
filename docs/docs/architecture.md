# Architecture

`:dawn4k` is the WebGPU backend of this repository: it implements the public
Graphiks WebGPU contract (`org.graphiks.webgpu`) on top of Dawn's C API. This
page describes the layered design, the threading model and the two deliberate
contract divergences every reviewer must know: the borrowed `ArrayBuffer` of a
mapped range, and the absence of a common `GPUDevice.lost`.

## Layers

| Layer | Location | Role |
| --- | --- | --- |
| Generated bindings | `:dawn4k-native` → `org.graphiks.dawn4k.native` | kextract output over the pinned Dawn release; never edited by hand |
| Dispatcher & runtime | `dawn4k/.../internal/NativeDispatcher.kt`, `DawnRuntime.kt`, `PendingOperation.kt` | one dedicated worker per runtime; serialized native operations, callback choreography and the event pump |
| Device sessions & registry | `dawn4k/.../internal/DeviceSession.kt`, `ResourceRegistry.kt` | per-device ownership of the adapter/device/queue references and of every reference acquired afterwards |
| Wrappers & mappers | `dawn4k/.../*.kt`, `dawn4k/.../mapper/*` | one `Dawn*` class per WebGPU interface; explicit name-based descriptor/enum tables |
| Public entry point | `dawn4k/.../DawnContext.kt`, `Adapter.kt`, `Device.kt` | `DawnContext.create(config)` → `requestAdapter` → `requestDevice` |

### Generated bindings

The `org.graphiks.dawn4k.native` package is generated by kextract from the Dawn
release pinned in `bindings/dawn.lock.json` (see
[Native Dawn binding](native-binding.md)). The backend consumes it as-is: no
numeric constant is ever assumed, and every enum/flag conversion goes through a
named-constant table in `mapper/Enums.kt` and friends.

### The serialized dispatcher and runtime

Every native downcall and every callback settle runs through **one dedicated
worker thread per runtime** (`NativeDispatcher`): a single-thread executor on
the JVM, a dedicated `kotlin.native.Worker` on Kotlin/Native. The affinity is a
Dawn contract, not an optimization — Dawn keys `WGPUDevice` error-scope stacks
per calling thread, so the push, the validated calls and the pop must share one
thread. Calls from any other thread are *routed* onto the worker, never
confined to or rejected by the calling thread.

`DawnRuntime` owns the `WGPUInstance`, discovers adapters and devices through
callback-bearing requests, and runs a periodic event pump
(`wgpuInstanceProcessEvents`) **only while callback registrations are open**.
Each in-flight operation is a `PendingOperation`: a native outcome that races
the coroutine waiting for it without ever leaking the native reference it
carries — a cancelled or abandoned wait still settles its late delivery on the
worker, releasing exactly once.

### Device sessions and the resource registry

A `DeviceSession` owns the adapter reference it acquired (`wgpuAdapterAddRef`),
the device and its queue. Every resource created afterwards is registered in
the session's `ResourceRegistry` with an optional destroy callback and a
mandatory release callback:

- **refcount-only** objects (samplers, layouts, pipelines, encoders, …) are
  released by `close()` right away;
- **destroy-backed** objects (buffers, textures, query sets) are destroyed by
  `close()` but keep a *tombstone* entry until the teardown, because Dawn hands
  back error objects whose handles must stay valid for late native errors.

Closing a session releases every registered reference — in reverse acquisition
order, before the device and adapter references — all on the dispatcher. The
debug counters (`debugRemainingRefs`, `debugOpenCallbacks`) are how the tests
assert ownership states without ever dereferencing released memory.

### Wrappers, guards and mappers

Each `Dawn*` wrapper borrows its native handle and refuses foreign objects
(`requireDawn*`) before any downcall can read a handle from another session.
Pass encoders release their handle on `end()` and the render bundle encoder on
`close()`, so each carries a Kotlin guard refusing late commands with an
`IllegalStateException` **before** a downcall — `finish()` on a command encoder
or bundle encoder deliberately does *not* release, so finishing twice is left
to Dawn's own validation. Labels are Kotlin-side metadata: the C label views
keep their defaults on every downcall.

## The borrowed `ArrayBuffer` limitation

`GPUBuffer.getMappedRange` returns an `ArrayBuffer` that **wraps the actual
mapped memory** — a borrowed view, never a CPU copy. Once the buffer is
unmapped (or closed), the memory goes back to the device and the view is
**invalid**. This is deliberately **not guarded**: no wrapper can know which
views are still held. Never read or write a mapped-range view after `unmap()` —
doing so is undefined behaviour, not a Kotlin exception.

## Published WebGPU contract

`GPUBuffer.usage` and `GPUTexture.usage` return typed masks, preserving the
descriptor's bits, including unknown ones. `GPUDeviceDescriptor.requiredLimits`
accepts partial `GPURequiredLimits`: null properties use the pinned Dawn header's
32-bit or 64-bit undefined sentinel; explicit zero remains zero. Nullable slots
in pipeline layouts, vertex buffers, color targets, pass attachments and bundle
formats retain their indices and use the corresponding native empty-slot form.

`GPUDevice.awaitLost()` observes a shared native `GPUDeviceLostInfo` result.
Cancelling one observer neither destroys the device nor cancels other observers.
The event pump progresses loss notifications while observers wait, even when no
other GPU operation is pending. Both callback routes are closed and proven
quiescent before the terminal result completes; later observers receive that
same result. Device `close()` explicitly destroys the native device, drains its
loss notification and releases owned references. A received native loss takes
precedence over a subsequent reentrant context close, without skipping callback
quiescence. The descriptor's uncaptured-error callback remains dispatcher-ordered.

## Target coverage versus `:dawn4k-native`

`:dawn4k-native` publishes bindings for a wide matrix (JVM, Android, macOS,
Linux x64, Android NDK, iOS and tvOS). The `:dawn4k` backend now declares the
same Kotlin matrix: JVM, Android, `macosArm64`, `linuxX64`, the three iOS
targets and the two tvOS targets. Android landed last, after `webgpu-api`
gained the borrowed-address `ArrayBuffer.wrap(address, size)` factory that a
GPU-mapped range requires (Graphiks-org/WebGPU#135):

| Target | `:dawn4k-native` | `:dawn4k` | Validation status |
| --- | --- | --- | --- |
| JVM | yes | yes (validated) | JVM tests and the GPU suite on Metal |
| `macosArm64` | yes | yes (validated, Metal) | K/N tests and the GPU suite on Metal |
| `linuxX64` | yes | yes | a Linux host with a GPU is required to validate |
| iOS (`arm64`/`x64`/simulator) | yes | yes | compiled, test binaries disabled like `:dawn4k-native` — validating requires a device or a booted simulator |
| tvOS (`arm64`/simulator) | yes | yes | compiled, test binaries disabled like `:dawn4k-native` — validating requires a device or a booted simulator |
| Android | yes | yes | compiled like `:dawn4k-native` (no host-test compilation); the borrowed mapped range goes through the upstream `ArrayBuffer.wrap(address, size)` |

On Android the borrowed `getMappedRange` view and the upload fast path ride
`webgpu-api`'s public factories: `wrap(address, size)` for the borrowed view,
and the direct `ByteBuffer` address for uploads, with a copy fallback whenever
the address accessor is unavailable — the same degradation contract as the
JVM actual. The `suite-acid-tests` dependency lives in a desktop-only
intermediate test source set because the published acid suite has no Apple
mobile variants. The public-contract acid witness (`PublicContractGpuTest`)
runs through standard desktop test tasks; common GPU tests also run on Apple
simulators. Test utilities report missing adapters, while strict CPU CI requires
an adapter. The JVM and Android runtimes share their
dispatcher and lock actuals through a `jvmSharedMain` source set.

## Ownership rules for callers

- close **sessions before their runtime**, and adapters/devices in reverse
  creation order (`DawnContext.close()` is idempotent, as is every `close()`);
- a resource belongs to exactly one device session — passing it to another
  device is refused before any handle is read;
- command buffers cannot be re-submitted, and a finished encoder must not be
  finished again (Dawn observes both as uncaptured validation errors).
